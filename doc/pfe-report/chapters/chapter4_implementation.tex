\chapter[Implementation]{Realization, implementation or experimentation}
\label{ch:implementation}

This chapter explains how the sprint-aligned design of
Section~\ref{sec:sprint-design} (Chapter~\ref{ch:architecture}) was turned into
working software. The goal was to deliver the five increments of
Table~\ref{tab:sprints} in order, each building on the previous one. The
approach was to implement each sprint against its design subsection, validate
the principal flows, and embed representative UI screenshots where they add
clarity. The outcome is a monorepo with a secured API, a document library with
asynchronous ingest, hybrid RAG, governance consoles, and operational tooling
described in the sections below.

\section{Implementation Steps by Sprint}

\subsection{Sprint 1: Authentication and access control}
\label{subsec:impl-sprint1}

The goal of Sprint~1 was to establish a secure perimeter before any document or
AI feature could be exposed. The approach followed
Subsection~\ref{subsec:sprint1-design}: short-lived access tokens kept in memory
on the web client (never in \texttt{localStorage}), refresh tokens in HttpOnly
cookies, a single in-flight refresh to avoid parallel rotations, and middleware
that enforces roles plus per-user restriction flags for document library and Ask
access. Profile avatars are served from a CORP-aware public route so browsers
can embed them across origins. The outcome is a complete sign-in, recovery,
profile, and role-based navigation shell, with integration tests confirming
flows \ref{fig:seq-01}--\ref{fig:seq-07}, \ref{fig:seq-23}, \ref{fig:seq-32},
and \ref{fig:seq-33}.

\subsection{Sprint 2: Document library and ingest pipeline}
\label{subsec:impl-sprint2}

Sprint~2 aimed to make organisational knowledge uploadable, searchable, and
governed by visibility rules. Uploads pass MIME and size checks, are stored on
disk, and enqueued for asynchronous processing. The worker extracts text per
format, chunks content with sentence-aware splitting and table preservation,
computes 768-dimensional embeddings, and persists indexed chunks. Visibility
(\texttt{ALL}, \texttt{DEPARTMENT}, \texttt{PRIVATE}) is enforced so
unauthorised callers receive a neutral 404 rather than revealing document
existence. Tags, favorites, recents, and versioning complete the library
experience. Integration tests cover document flows
\ref{fig:seq-08}--\ref{fig:seq-10} and \ref{fig:seq-24}--\ref{fig:seq-29}.

\subsection{Sprint 3: Search, RAG and conversations}
\label{subsec:impl-sprint3}

The goal of Sprint~3 was to let authorised users find information semantically
and receive cited, streaming answers grounded in their accessible corpus. Hybrid
retrieval combines dense vectors and full-text search, fuses rankings, reranks
with Gemini, and streams results over SSE. Algorithm~\ref{alg:rag} summarizes
the Ask endpoint logic.

\begin{algorithm}[H]
\caption{Hybrid RAG Ask pipeline (simplified)}
\label{alg:rag}
\begin{algorithmic}[1]
\State Authenticate user and resolve \texttt{readableDepartmentIds}
\State Optimize query (type, topic, rewrite, optional multi-hop)
\State Retrieve dense vectors (pgvector) and sparse FTS (BM25-style)
\State Fuse rankings with weighted reciprocal rank fusion (RRF)
\State Rerank top chunks with Gemini; optionally expand neighbor chunks
\State Stream SSE events: \texttt{sources}, \texttt{token}, optional \texttt{correction}
\State Persist conversation message with citations and confidence
\State Optionally cache answer keyed by prompt version and filters
\end{algorithmic}
\end{algorithm}

The Ask UI consumes SSE streams and renders markdown with sanitized links.
Conversation threads, message persistence, and thumbs-up/down feedback round out
the assistant experience. Search, Ask, and conversation flows
(\ref{fig:seq-11}--\ref{fig:seq-14}, \ref{fig:seq-30}, \ref{fig:seq-31}) were
validated by automated integration tests.

\subsection{Sprint 4: Governance and notifications}
\label{subsec:impl-sprint4}

Sprint~4 addressed organisational governance: administrators manage users,
departments, and audit trails; managers oversee department-scoped activity;
and all roles receive timely notifications. Department access logic computes
readable and manageable scopes including inherited manager and viewer rights.
Administrators can bulk-restrict users, import CSV rosters with formula-injection
escaping, merge departments, export KPIs, and review document audit logs.
Managers access department dashboards; the notification service emits automatic
events on document lifecycle changes and supports manual announcements with
attachments. Document previews use blob URLs for PDFs and images; the inbox
polls for unread badges. Admin, manager, and notification flows
(\ref{fig:seq-15}--\ref{fig:seq-21}, \ref{fig:seq-34}--\ref{fig:seq-41}) were
confirmed by integration tests.

\section{Difficulties Encountered and Solutions}

\begin{table}[H]
\centering
\caption{Implementation challenges and resolutions}
\label{tab:difficulties}
\begin{tabularx}{\textwidth}{|>{\RaggedRight\arraybackslash}p{2.8cm}|>{\RaggedRight\arraybackslash}p{0.30\linewidth}|Y|}
\hline
\textbf{Difficulty} & \textbf{What went wrong} & \textbf{How it was resolved} \\
\hline
Avatar not displayed &
Browsers blocked cross-origin profile images because the avatar route lacked a permissive CORP header. &
The API now allows cross-origin embedding for public avatar responses. \\
\hline
Random logout on navigation &
Parallel refresh requests rotated the refresh token twice, invalidating the session. &
The web client serialises refresh into a single in-flight promise so only one rotation occurs. \\
\hline
Next.js dev webpack errors with avatars &
The optimised image component correlated with RSC bundling issues in development. &
Profile avatars use a standard HTML image element instead of the framework image wrapper. \\
\hline
Gemini rate limits &
External API throttling caused intermittent failures under load. &
Answers are cached with TTL; retries use exponential backoff. \\
\hline
Spreadsheet chunking &
Tables split mid-row lost row semantics in retrieved chunks. &
Chunking preserves table structure as markdown before embedding. \\
\hline
\end{tabularx}
\end{table}
