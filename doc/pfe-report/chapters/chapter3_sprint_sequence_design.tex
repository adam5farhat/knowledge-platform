\subsection{Sprint 1: Authentication and access control}\label{subsec:sprint1-design}

Sprint~1 defines how people enter and move through the platform. It covers
sign-in and sign-out, password recovery, profile management, and the rules that
limit access when an account or feature is restricted.

\sprintstructural{1}%
  {Sprint 1 use-case diagram — Authentication and access control}{fig:sprint1-use-cases}%
  {Sprint 1 domain class diagram — Authentication and access control}{fig:sprint1-class}

\sprintsequences{1}

\sprintflowgroup{Signing in and managing the session}

\paragraph{User sign-in.}
A user enters email and password; the platform verifies the credentials, applies
account lockout after repeated failures, and opens a secure session with a
short-lived access token and a protected refresh cookie.
\seqdiagram{seq-01-login}{User sign-in}{sign-in flow}{fig:seq-01}

\paragraph{Silent session renewal.}
When the access token expires, the web application renews the session in the
background so the user can continue working without signing in again.
\seqdiagram{seq-02-refresh-token}{Silent session renewal}{token refresh flow}{fig:seq-02}

\paragraph{User sign-out.}
Signing out ends the active session on the server and removes the refresh cookie
from the browser, so the account cannot be reused from that device without a new
sign-in.
\seqdiagram{seq-03-logout}{User sign-out}{sign-out flow}{fig:seq-03}

\paragraph{Forgotten password recovery.}
A user who forgot their password requests a reset link by email, then sets a new
password through a time-limited link. Existing sessions are closed once the
password changes.
\seqdiagram{seq-04-password-reset}{Forgotten password recovery}{password reset flow}{fig:seq-04}

\paragraph{Changing password while signed in.}
A signed-in user can change their password after confirming the current one.
Successful change closes other active sessions for safety.
\seqdiagram{seq-05-change-password}{Changing password while signed in}{change-password flow}{fig:seq-05}

\sprintflowgroup{Profile, permissions and session context}

\paragraph{Updating the user profile.}
Users can update personal details such as display name and contact information.
Some changes, such as email updates, require the session to be renewed for
security.
\seqdiagram{seq-06-profile-update}{Updating the user profile}{profile update flow}{fig:seq-06}

\paragraph{Blocking access to a restricted feature.}
Before sensitive actions run, the server checks whether the user is allowed to
use the document library or AI-powered search. If not, the request is rejected
with a clear permission error (see Figure~\ref{fig:seq-33} for the page shown to
the user).
\seqdiagram{seq-07-feature-restriction}{Blocking access to a restricted feature}{feature gate check}{fig:seq-07}

\paragraph{Loading the signed-in user's context.}
After authentication, the application loads the user's role, department
memberships, and active restrictions so menus and pages can be adapted
immediately.
\seqdiagram{seq-23-get-auth-me}{Loading the signed-in user's context}{session context load}{fig:seq-23}

\sprintflowgroup{Pages shown before or outside normal access}

\paragraph{Registration information page.}
Self-service account creation is not offered. The registration page explains that
administrators create accounts, which keeps user provisioning under organisational
control.
\seqdiagram{seq-32-register-info-static}{Registration information page}{static information page}{fig:seq-32}

\paragraph{Restricted feature explanation page.}
When a user reaches a feature they are not allowed to use, the application shows
a dedicated explanation page with guidance instead of a generic error message.
This page is shown in the browser; the permission check itself is illustrated in
Figure~\ref{fig:seq-07}.
\seqdiagram{seq-33-restricted-page-ux}{Restricted feature explanation page}{client explanation page}{fig:seq-33}

\subsection{Sprint 2: Document library and ingest}\label{subsec:sprint2-design}

Sprint~2 introduces the document library: uploading files, preparing them for
search, browsing and downloading content, and managing versions and metadata
within department visibility rules.

\sprintstructural{2}%
  {Sprint 2 use-case diagram — Document library and ingest}{fig:sprint2-use-cases}%
  {Sprint 2 domain class diagram — Document library and ingest}{fig:sprint2-class}

\sprintsequences{2}

\sprintflowgroup{Uploading and preparing documents}

\paragraph{Uploading a document.}
A user uploads a file with basic metadata. The platform stores the file, records
the document in the library, and queues background processing so the user does
not have to wait for indexing to finish.
\seqdiagram{seq-08-document-upload}{Uploading a document}{upload flow}{fig:seq-08}

\paragraph{Background document processing.}
After upload, a background worker extracts text, splits it into meaningful
passages, creates searchable embeddings, and stores them so the document can
later appear in semantic search and AI answers.
\seqdiagram{seq-09-document-ingest-worker}{Background document processing}{ingest pipeline}{fig:seq-09}

\paragraph{Reprocessing an existing version.}
An administrator can trigger reprocessing of a document version---for example
after improving the indexing pipeline---without uploading the file again.
\seqdiagram{seq-29-document-reprocess}{Reprocessing an existing version}{reprocess flow}{fig:seq-29}

\sprintflowgroup{Browsing and downloading}

\paragraph{Downloading a document file.}
An authorised user downloads the original file. The platform verifies department
access before sending the file.
\seqdiagram{seq-10-document-read-download}{Downloading a document file}{download flow}{fig:seq-10}

\paragraph{Browsing the document library.}
Users browse the library with filters and pagination. Results show summary
information suitable for the catalogue view without loading full text content.
\seqdiagram{seq-24-documents-list}{Browsing the document library}{library list flow}{fig:seq-24}

\paragraph{Opening a document detail view.}
Opening a document shows its metadata, current version, tags, processing status,
and the information needed for preview or further actions.
\seqdiagram{seq-25-document-detail}{Opening a document detail view}{document detail flow}{fig:seq-25}

\paragraph{Favourites and recently viewed documents.}
Users can mark documents as favourites and revisit recently opened items from the
library home view.
\seqdiagram{seq-26-favorites-recents}{Favourites and recently viewed documents}{favourites and recents flow}{fig:seq-26}

\sprintflowgroup{Editing metadata and versions}

\paragraph{Updating document metadata.}
Authorised users can edit title, description, tags, and visibility. Changes are
recorded for traceability.
\seqdiagram{seq-27-patch-document-metadata}{Updating document metadata}{metadata update flow}{fig:seq-27}

\paragraph{Publishing a new document version.}
Uploading a replacement file creates a new version, starts fresh indexing, and
keeps earlier versions available for audit and rollback.
\seqdiagram{seq-28-document-new-version}{Publishing a new document version}{new version flow}{fig:seq-28}

\subsection{Sprint 3: Search, RAG and conversations}\label{subsec:sprint3-design}

Sprint~3 adds intelligent search over the document base and a conversational
workspace where users can ask questions and receive answers grounded in
organisational content.

\sprintstructural{3}%
  {Sprint 3 use-case diagram — Search, RAG and conversations}{fig:sprint3-use-cases}%
  {Sprint 3 domain class diagram — Search, RAG and conversations}{fig:sprint3-class}

\sprintsequences{3}

\sprintflowgroup{Search and AI-assisted answers}

\paragraph{Semantic search.}
A user enters a natural-language query; the platform finds the most relevant
document passages and returns ranked excerpts for direct exploration.
\seqdiagram{seq-11-semantic-search}{Semantic search}{semantic search flow}{fig:seq-11}

\paragraph{Asking a question with AI assistance.}
In the Ask workspace, the platform retrieves relevant passages, combines keyword
and semantic matching, and streams a structured answer with source references to
the user in real time.
\seqdiagram{seq-12-ask-rag-sse}{Asking a question with AI assistance}{RAG answer flow}{fig:seq-12}

\sprintflowgroup{Conversations and answer quality}

\paragraph{Creating conversations and adding messages.}
Users open a new conversation, ask questions, receive answers, and can
automatically generate a short title from the first question. Opening an existing
thread loads its full history (see Figure~\ref{fig:seq-30}).
\seqdiagram{seq-13-conversation-and-messages}{Creating conversations and adding messages}{conversation messaging flow}{fig:seq-13}

\paragraph{Rating an answer.}
After receiving an answer, users can submit positive or negative feedback with an
optional comment, helping administrators monitor answer quality over time.
\seqdiagram{seq-14-answer-feedback}{Rating an answer}{answer feedback flow}{fig:seq-14}

\paragraph{Managing conversation threads.}
Users list past conversations, open a thread with its message history, rename a
thread, or delete it when it is no longer needed.
\seqdiagram{seq-30-conversations-crud-supplement}{Managing conversation threads}{conversation management flow}{fig:seq-30}

\paragraph{Administrator feedback overview.}
Administrators consult aggregated feedback metrics---volume, satisfaction ratio,
and recent comments---to track how well AI answers are received across the
organisation.
\seqdiagram{seq-31-admin-feedback-stats}{Administrator feedback overview}{feedback statistics flow}{fig:seq-31}

\subsection{Sprint 4: Governance and notifications}\label{subsec:sprint4-design}

Sprint~4 supports day-to-day governance: keeping users informed through
notifications, giving managers visibility over their teams, and providing
administrators with tools to manage users, departments, and documents at scale.

\sprintstructural{4}%
  {Sprint 4 use-case diagram — Governance and notifications}{fig:sprint4-use-cases}%
  {Sprint 4 domain class diagram — Governance and notifications}{fig:sprint4-class}

\sprintsequences{4}

\sprintflowgroup{Notifications}

\paragraph{Automatic notification when a document is added.}
When a new document is published, subscribed department members receive an inbox
notification without delaying the upload experience.
\seqdiagram{seq-15-notification-automatic}{Automatic notification when a document is added}{document-created notification}{fig:seq-15}

\paragraph{Sending a manual announcement.}
Administrators and managers can send targeted announcements, optionally with
attachments, to selected users or departments.
\seqdiagram{seq-16-notification-manual-send}{Sending a manual announcement}{manual announcement flow}{fig:seq-16}

\paragraph{Reading and managing notifications.}
Users open their notification inbox, see unread items, mark messages as read,
and access any attached content.
\seqdiagram{seq-17-notification-inbox}{Reading and managing notifications}{notification inbox flow}{fig:seq-17}

\sprintflowgroup{Manager workspace}

\paragraph{Manager department overview.}
Managers view the departments they oversee and inspect each department's member
list to understand team composition.
\seqdiagram{seq-18-manager-dashboard}{Manager department overview}{manager department view}{fig:seq-18}

\sprintflowgroup{Administrator governance}

\paragraph{Creating a user account.}
Administrators create accounts with an initial role, department access, and
optional feature restrictions. Credentials are shared through organisational
channels.
\seqdiagram{seq-19-admin-user-create}{Creating a user account}{user creation flow}{fig:seq-19}

\paragraph{Merging two departments.}
Department merge moves documents, access rights, and memberships from one
department into another while preserving data consistency.
\seqdiagram{seq-20-admin-department-merge}{Merging two departments}{department merge flow}{fig:seq-20}

\paragraph{Replacing a user's department access in bulk.}
Administrators can replace all department-access entries for one user in a single
operation, which simplifies onboarding and access reviews.
\seqdiagram{seq-21-admin-department-access-bulk}{Replacing a user's department access in bulk}{bulk access update flow}{fig:seq-21}

\paragraph{Creating a department.}
Administrators add a new organisational unit with a unique identifier. The
operation is logged for audit purposes.
\seqdiagram{seq-34-admin-department-create}{Creating a department}{department creation flow}{fig:seq-34}

\paragraph{Granting or revoking single department access.}
Fine-grained actions add or remove access to one department for one user without
rewriting the entire access matrix.
\seqdiagram{seq-35-dept-access-single-post-delete}{Granting or revoking single department access}{single access grant or revoke}{fig:seq-35}

\paragraph{Platform-wide statistics.}
Administrators view high-level indicators such as user count, document volume,
conversation activity, and indexing backlog.
\seqdiagram{seq-36-admin-stats}{Platform-wide statistics}{admin statistics flow}{fig:seq-36}

\paragraph{Activity log and export.}
Administrators browse recent platform activity and export filtered events to
spreadsheet format for offline review.
\seqdiagram{seq-37-admin-activity-export}{Activity log and export}{activity log export flow}{fig:seq-37}

\paragraph{Document change audit log.}
Administrators review and export a platform-wide log of document changes---
metadata, visibility, and version updates---to support compliance and access
reviews.
\seqdiagram{seq-38-admin-document-audit}{Document change audit log}{document audit log flow}{fig:seq-38}

\paragraph{Exporting the document catalogue.}
Administrators export the document inventory---titles, departments, tags, and
processing status---for reconciliation or reporting.
\seqdiagram{seq-39-admin-documents-csv-export}{Exporting the document catalogue}{document catalogue export}{fig:seq-39}

\paragraph{Deleting multiple documents.}
Administrators remove a selected set of documents in one guarded operation,
including stored files and related records.
\seqdiagram{seq-40-admin-bulk-delete-documents}{Deleting multiple documents}{bulk delete flow}{fig:seq-40}

\paragraph{Updating or locking a user account.}
Administrators adjust roles, restrictions, or active status. A sign-in lock
prevents further authentication attempts for a defined period without affecting
unrelated accounts.
\seqdiagram{seq-41-admin-user-patch-lock}{Updating or locking a user account}{user update and lock flow}{fig:seq-41}

\subsection{Sprint 5: Operations, testing and deployment}\label{subsec:sprint5-design}

Sprint~5 focuses on operability: confirming that the platform is healthy,
packaging it for reproducible deployment, and validating behaviour through
automated tests and AI quality checks.

\sprintstructural{5}%
  {Sprint 5 use-case diagram — Operations, testing and deployment}{fig:sprint5-use-cases}%
  {Sprint 5 domain class diagram — Operations, testing and deployment}{fig:sprint5-class}

\sprintsequences{5}

\paragraph{Service health check.}
Monitoring tools call a public health endpoint to verify that the application is
running and can reach its database and cache services.
\seqdiagram{seq-22-health-check}{Service health check}{health check flow}{fig:seq-22}

\subsubsection{Operational deliverables}
\label{subsubsec:sprint5-operations}

\paragraph{Integration test suite.}
An automated test suite exercises the main user journeys---authentication,
documents, search, conversations, administration, and manager views---so
regressions are detected before release.

\paragraph{Containerised deployment.}
The platform is packaged with its database, cache, API, and web application so the
full environment can be started consistently on any workstation or in continuous
integration.

\paragraph{RAG quality evaluation.}
A repeatable evaluation workflow runs predefined questions through the Ask
pipeline and scores answer quality, producing reports that can be compared across
development iterations.
