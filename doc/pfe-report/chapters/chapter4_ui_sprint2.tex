\subsubsection{Implemented web interfaces}
\label{subsubsec:impl-s2-ui}

The document library lets authorised users browse department-scoped collections,
inspect file details, upload and version documents, preview content, and follow
asynchronous ingest status. Each screen below is described with purpose, access,
components, workflow, and expected behaviour.

\paragraph{Department library browse.}
\uiexplain
{Present the organisational document catalogue within the user's authorised
department scope, with filters and navigation to specialised library views.}
{Home hub Documents tile, or authenticated navigation to the library route.}
{Sidebar scopes (for example Recent, Favourites, Archived); department or
collection cards; search and filter controls; primary actions such as upload when
permitted.}
{The user browses cards or applies filters, then opens a document to inspect
details. Managers and administrators may start an upload from this surface.}
{Only documents permitted by visibility and department rules appear; unauthorised
items are omitted rather than revealed.}
\uiscreenshot{ui-library-departments.png}{Department library browse with sidebar navigation and filter controls}{Department library browse}{fig:ui-library}

\paragraph{Document detail side panel.}
\uiexplain
{Show metadata and actions for a selected document without leaving the library
context.}
{Selecting a document card or row in the library opens the detail panel.}
{Title and description; ingest or readiness status; visibility and tags; actions
such as Open, Download, Favourite, and Versions.}
{The user reviews metadata, downloads or previews the file, stars the document,
or opens version management when authorised.}
{Actions respect role and ownership rules; status reflects the latest processing
state of the active version.}
\uiscreenshot{ui-document-details.png}{Document detail side panel with metadata and action buttons}{Document detail side panel}{fig:ui-doc-details}

\paragraph{Document upload modal.}
\uiexplain
{Allow authorised users to add a new document with file content and descriptive
metadata, then queue background ingest.}
{Upload control or floating action on the library (managers and administrators).}
{Multi-step modal: file drop zone; metadata fields (title, description,
visibility); tag selection; confirm and cancel actions.}
{The user selects a file, completes metadata, and confirms. The client uploads the
payload; the API stores the file and enqueues processing (Figure~\ref{fig:seq-08}).}
{Rejected files fail validation (type or size); accepted uploads appear in the
library with a pending or processing state until ingest completes.}
\uiscreenshot{ui-document-upload.png}{Multi-step upload modal with file drop zone and metadata fields}{Document upload modal}{fig:ui-doc-upload}

\paragraph{Recent documents.}
\uiexplain
{Help users return quickly to documents they opened recently.}
{Library sidebar entry Recent.}
{Filtered list or cards of recently viewed documents; active sidebar highlight.}
{The user opens Recent, then selects an item to reopen its detail view.}
{The list is personal and permission-aware; documents no longer accessible are
not shown.}
\uiscreenshot{ui-library-recent.png}{Recent documents scope with sidebar highlight}{Recent documents}{fig:ui-library-recent}

\paragraph{Favourites view.}
\uiexplain
{Surface documents the user has explicitly starred for repeated access.}
{Library sidebar entry Favourites.}
{List of favourited documents with the same card or row affordances as the main
library.}
{The user stars a document from its detail panel, then revisits it from
Favourites.}
{Favourite state persists per user; unstarring removes the item from this scope.}
\uiscreenshot{ui-library-favorites.png}{Favourites scope listing starred documents}{Favourites view}{fig:ui-library-favorites}

\paragraph{Table view.}
\uiexplain
{Offer a dense, column-oriented layout for scanning metadata and applying
tabular filters.}
{Layout toggle on the library (card versus table).}
{Column headers (title, department, status, tags, dates); row selection; filter
controls aligned with columns.}
{The user switches to table layout, sorts or filters columns, and opens a row for
details.}
{The same access rules as card view apply; layout preference does not change
authorisation.}
\uiscreenshot{ui-library-table-view.png}{Department library in table layout with column filters}{Table view}{fig:ui-library-table}

\paragraph{Ingest processing status.}
\uiexplain
{Make asynchronous document processing visible so users know when a file becomes
searchable and ready for Ask.}
{Document detail panel while a version is still being ingested.}
{Processing badge; progress indicator; metadata retained during the wait;
disabled or limited actions until ready.}
{After upload, the user keeps the detail panel open or revisits it until status
reaches \textbf{READY} (validated end state in Chapter~\ref{ch:validation}).}
{Progress advances until success or failure; failed ingest surfaces an error
state without blocking the rest of the library.}
\uiscreenshot{ui-document-processing.png}{File detail panel during ingest with processing badge and progress bar}{Ingest processing status}{fig:ui-doc-processing}

\paragraph{In-app PDF preview.}
\uiexplain
{Allow authorised users to read supported documents in the browser without an
immediate download.}
{Open or Preview action from the document detail panel.}
{Modal viewer; page navigation; close control; document title context.}
{The user opens preview, navigates pages, then closes the modal to return to the
library.}
{Only permitted users can load the file stream; unsupported types fall back to
download rather than a broken viewer.}
\uiscreenshot{ui-document-preview.png}{In-app PDF preview modal with navigation controls}{In-app PDF preview modal}{fig:ui-doc-preview}

\paragraph{Version archive dialog.}
\uiexplain
{Expose version history and allow authorised users to upload a new version or
request reprocessing of an existing one.}
{Versions action on the document detail panel (managers and administrators).}
{Ordered version list; upload-new-version control; reprocess action; status of
each version.}
{The user inspects prior versions, uploads a replacement file, or triggers
reprocess; ingest runs again for the affected version.}
{Earlier versions remain available for audit; the active version updates when
processing succeeds.}
\uiscreenshot{ui-document-versions.png}{Version archive dialog with upload and reprocess actions}{Version archive dialog}{fig:ui-doc-versions}
